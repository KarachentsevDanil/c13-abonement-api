# LIB-218. Онлайн-продовження видачі — специфікація

## Критерії приймання

1. Читач може продовжити видачу через API: `POST /loans/:id/renew`.
2. Кожне продовження — +14 днів до поточної дати повернення (`due_at`); не більше 2 продовжень на видачу.
3. Продовження заборонене, якщо на книгу є активна бронь іншого читача.
4. Продовження заборонене, якщо в читача є хоча б одна прострочена видача.
5. Відповідь: 200 з новою `due_at`; відмова — 409 з кодом причини `LIMIT_REACHED` | `HOLD_EXISTS` | `OVERDUE_LOANS`.

## Рішення після дослідження (plan mode)

| # | Питання агента | Рішення |
| --- | --- | --- |
| 1 | «Прострочена видача» означає неповернуту видачу з `due_at` раніше за поточний момент? Чи рахується сама видача, яку продовжують? | Так, `due_at < clock.now()`. Сама видача теж рахується: прострочену видачу онлайн не продовжити, лише на стійці. |
| 2 | Що робити, якщо catalog-api не відповів? | Продовження не виконуємо: відповідь 503, `due_at` без змін. |
| 3 | `holds.activeForBook` повертає всі броні книги, зокрема бронь самого читача. Чи блокує вона продовження? | Ні. Блокує лише бронь іншого читача, як в умові 3. |
| 4 | Якщо причин відмови кілька, який код повертати? | Перший за порядком: `LIMIT_REACHED`, `OVERDUE_LOANS`, `HOLD_EXISTS`. |
| 5 | `src/loans/adminRenew.ts` уже продовжує видачу. Брати його за зразок? | Ні. Це продовження на стійці: нова дата там рахується від сьогодні через `new Date()`. Онлайн рахуємо від `due_at` через `clock.now()`. Зміни в `adminRenew` є non-goal. |

## Non-goals

- зміни в `src/loans/adminRenew.ts`: продовження на стійці лишається як є;
- зміни в `src/notify` і шаблонах листів;
- повторні спроби запиту до catalog-api: при збої потрібна швидка відповідь 503.
